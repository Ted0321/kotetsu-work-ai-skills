# チャート試着室 — 配布用プロンプト

同じデータを10形式で描き分け、「誰に何を言いたいか」で1枚に絞り込むページを作らせる指示文。
第2段階として、選んだ1枚をPowerPointのネイティブチャートに起こす指示文も置いている。

このリポジトリの [`index.html`](./index.html) は、下記プロンプトで作れる完成形の一例。

---

## 第1段階 — 10形式を一気に描かせる

> 使い方: 末尾の「データ」を自分のものに差し替えて、まるごと貼る。

```text
あなたはデータビジュアライゼーションの設計者です。
渡すデータについて、考えられるチャート形式を10通り作り、1つのHTMLページに並べてください。
目的は「どのチャートで見せるべきか」を実物を見ながら選べるようにすることです。

## 作るもの

自己完結した1枚のHTMLファイル。外部CDNを使わず、CSSとJSはすべてインラインに書く
（オフラインで開けること）。チャートはライブラリを使わずSVGで描く。

構成:
1. ヘッダー — データの一言説明と、全体で何が起きているかを1文
2. 目的セレクタ（後述。ここが本体）
3. 10枚のチャートをカードでグリッド配置
4. 「数値で見る」— 折りたたみの元データ表

各カードに入れるもの:
- チャート名（例: 構成比の変化）
- 形式名（例: 100%積み上げ）
- チャート本体
- その形式で「何が言えて、何が言えないか」を1文

## 10形式（この10個を必ず全部作る）

1.  折れ線 ............ 時系列の動き
2.  積み上げ棒 ........ 合計と構成の推移
3.  100%積み上げ ...... 構成比の変化
4.  ウォーターフォール .. 期首から期末への増減分解
5.  バブル ............ 規模 × 成長 × 収益性の3軸
6.  2×2マトリクス ..... ポジショニング・優先度
7.  ヒートマップ ....... 時期 × カテゴリの濃淡
8.  横棒ランキング ..... 現時点の大小
9.  スロープグラフ ..... 2時点間の変化と順位の入れ替わり
10. 小倍数 ............ カテゴリを並べて平等に比較

データの性質上どうしても成立しない形式があれば、無理に描かず
「このデータでは成立しない理由」をカードに書くこと。
軸を捏造して埋めないこと。

補足:
- ヒートマップは他の9枚と同じ指標である必要はない。積み上げ棒と内容が重複するなら、
  解約率・利益率など別の指標を採ってよい（そのぶんページ全体の情報量が増える）
- 2×2のしきい値は分析者が置く線なので、値を明示し、
  「データが決めた線ではない」ことをカードに書くこと

## 目的セレクタ（この機能が中心）

ページ上部に「誰に、何を言いたいですか」というボタンを4つ置く。
目的はデータの内容から自分で考えて設定する
（例: 役員に投資判断を迫る / 現場に危機感を伝える / 経営会議で現状報告する / 再編を提案する）。

押したときの挙動:
- 推奨する1枚以外のカードを不透明度0.24まで沈める（消さない。比較できることが大事）
- 推奨する1枚に枠線でスポットライトを当てる
- なぜその1枚なのかの理由を2文で表示する。理由には必ずデータ上の具体的な数字を含める
- 「すべて表示」で元に戻せる
- 切り替えは0.35秒のトランジション（動画で見せるため）

目的が変われば推奨も変わること。4つとも同じ答えになるなら、目的の設定を見直す。

## チャート品質のルール（必ず守る）

【色】
- 色はカテゴリ（実体）に紐づける。製品Aは10枚すべてで同じ色にする。
  チャートごとに色を振り直さない
- 系列は最大4つまで。5つ以上なら上位4つ +「その他」に畳む
- 濃淡（順序尺度）は1色の明暗だけで表す。虹色にしない
- 増減は青（増）と赤（減）、中間は無彩色
- 文字に系列色を使わない。ラベル・数値・凡例は本文色にし、
  識別は隣に置いた色マークが担う（薄い色は文字にすると読めない）
- 色覚多様性でも見分けられる組み合わせにする。赤×緑、オレンジ×黄、
  明度の近い同系色を隣り合わせにしない。識別を色だけに頼らせず、
  直接ラベルか凡例を必ず併置する

【マーク】
- 棒の太さは最大24px。バンドを埋め尽くさない
- 線は2px、マーカーは直径8px以上
- px指定は「設計サイズでの値」。SVGを設計サイズより拡大しないこと
  （viewBoxと同じ幅で max-width を掛ける）。伸縮させると24pxの棒が30pxに太り、
  8pxのマーカーが6pxに縮んで、指定が意味をなさなくなる
- 積み上げの各段の間、隣接する棒の間は、背景色の2pxの隙間で分ける（枠線で囲まない）
- グリッド線は1pxの実線で、背景から一段だけ濃い色。破線にしない
- 目盛りはキリのいい数字に丸める

【ラベル】
- すべての点に数値を書かない。端・極値・主役の系列だけに書く
- ラベルが重なるなら、ずらさずに諦めて凡例に任せる
  （ずらすと線から離れて、どの系列の値か分からなくなる）
- 凡例はページ上部に1つだけ置き、各カードには繰り返さない
  （10枚に同じ凡例が並ぶと場所を食い、動画では特に邪魔になる）
- 単独で見ても意味が通る必要があるチャートだけ、直接ラベルを添える

【やらないこと】
- 3D、影付き、グラデーション背景
- 2軸グラフ（左右で別スケール）。単位が違うなら2枚に分ける
- 円グラフを主役にする（構成比は100%積み上げか横棒で）
- 数値を全部書き込む

【検算】
- ウォーターフォールは、分解した各項の合計が期末の値に厳密に一致すること。
  一致しない分解は出さない
- 100%積み上げは各期の合計が100%になること
- すべてのチャートの数値が、末尾の元データ表と一致すること

【見た目】
- ライトモードとダークモードの両方に対応する。色はCSS変数で定義し、
  prefers-color-scheme と [data-theme] の両方で切り替える
  （どちらか片方だけだと、片方のテーマで文字が読めなくなる）
- 日本語のWebフォントは読み込まない（重い）。システムフォントで、
  ウェイトと字送りで階層を作る
- 横スクロールを発生させない

## 出す前の自己チェック

以下を全部確認し、直してから出すこと。

1. 10枚すべてが描画され、コンソールエラーが0件か
2. 同じカテゴリが全チャートで同じ色になっているか
3. ラベルが他の要素と重なっていないか
   （特に 2×2の象限名 / バブルのラベル / 折れ線の右端 の3か所）
4. ウォーターフォールの合計が期末の値と一致するか
5. 目的を切り替えたとき、推奨されるチャートが実際に変わるか
6. ダークモードで文字が読めるか
7. 各カードの「何が言えないか」が、そのチャートの実際の弱点を突いているか
   （褒め言葉だけになっていないか）

## データ

［ここにCSVを貼るか、ファイルのパスを書く］

データの形: ［例: 3年分 × 製品別の売上（百万円）］
補足: ［例: 全社では微増だが、主力製品は落ちている］
```

## 第2段階 — 選んだ1枚をPowerPointにする

> 第1段階のあと、続けて貼る。

```text
試着室から「＿＿＿＿」を選びました。これをPowerPointのスライドにしてください。

## 必須条件

- 画像の貼り付けではなく、PowerPointのネイティブチャートにすること。
  開いた人が数値も色も編集できる状態にする（pptxgenjs の addChart() を使う）
- スライドサイズは16:9ワイド（13.3 × 7.5インチ）
- 系列の色は試着室とそろえる

## スライドの構成（コンサル資料の基本形）

1. キッカー — 誰向け・何の話かを小さく1行
2. メッセージライン — そのチャートから言える結論を1文。25pt前後・太字・左揃え。
   「〜の推移」という題名ではなく、「〜が起きている」「〜すべき」という主張にする
3. チャート本体
4. 出所 — 下部に小さく

## やらないこと

- タイトル下の下線、装飾の色帯、スライド端の縦ストライプ
  （AI製スライドの典型なので使わない）
- 本文の中央揃え（タイトル以外は左揃え）
- 文字がボックスからはみ出たまま出すこと

## PowerPointに標準で無いチャートの作り方

- ウォーターフォール: 積み上げ棒で作る。一番下に背景色（白）の「土台」系列を置いて
  見えなくし、その上に「増益」「減益」を別系列で積む
  （各カテゴリでどちらか一方だけが値を持つようにする）
- 積み上げ棒でデータラベルを出すときの位置は ctr / inEnd / inBase のいずれか。
  outEnd はファイルが壊れる
- 凡例に「土台」が出てしまうので、凡例は切って、色の四角と文字で自前で置く

## 完成後の確認

- チャートが画像ではなく、編集可能なオブジェクトとして入っているか
- 文字がはみ出ていないか
- 系列の色が試着室と同じか
```

## X投稿用（短縮版）

長い指示が難しい場面向け。品質ルールを削っているぶん、出力のばらつきは大きくなる。

```text
このデータで、考えられるチャート形式を10通り作って、1枚のHTMLに並べて。
折れ線 / 積み上げ棒 / 100%積み上げ / ウォーターフォール / バブル /
2×2マトリクス / ヒートマップ / 横棒ランキング / スロープグラフ / 小倍数。

各チャートには「何が言えて、何が言えないか」を1文つけて。
色は形式ごとではなくカテゴリごとに固定（製品Aは10枚とも同じ色）。
ライブラリは使わずSVGで、ダークモードにも対応して。

そのうえで上部に「誰に、何を言いたいか」を選ぶボタンを4つ置いて。
押したら推奨の1枚以外を薄くして、なぜその1枚なのかを数字つきで説明して。

［データを貼る］
```

## 検証結果（2026-08-13）

まっさらなセッションに精密版を貼り、**別データ**（SaaSのプラン別ARR: 3年 × 4プラン、
契約社数・粗利率・解約率つき）で一発生成させた結果、自己チェック7項目すべてを満たした。

| 観点 | 結果 |
|---|---|
| 10形式すべて描画 | ○ 成立しない形式なし |
| カテゴリと色の固定 | ○ 10枚とも同じ色 |
| ラベル衝突 | ○ 0件（2×2の象限名・バブル・折れ線の右端とも） |
| ウォーターフォールの検算 | ○ 1,380 +340 +35 −90 −135 = 1,530 |
| 目的で推奨が変わる | ○ 4目的が4枚とも別（バブル / ヒートマップ / 積み上げ棒 / 滝） |
| ダークモード | ○ 単純反転ではなく暗い面用に色を作り直していた |
| 「何が言えないか」の質 | ◎ 下記のとおり実際の弱点を突いていた |

「言えないこと」の出力例（プロンプトの自己チェック7が最も効いた）:

> 100%積み上げ — 縦軸が常に100%なので全社ARRが増えたのか減ったのかは完全に消える。
> 全プランが半減しても、この絵はまったく同じ形になる。

> ヒートマップ — 色は順序しか表さないので「44%は28%の1.6倍」という量の差は読めず、
> ARRの規模が入らないぶん、小さい事業の悲鳴を実際より大きく見せてしまう。

> 小倍数 — 共通スケールの代償として Legacy 190→55（−71.1%）の急落がパネル下端で潰れる。
> 当事者にとっては事業消滅の3年間なのに、絵の上ではほぼ平らな線になってしまう。

指示していないのに足されたもの: テーマ切替ボタン、カード番号。

**この検証で見つかった不足は、上のプロンプトに反映済み**（凡例の重複／px指定とSVG伸縮の
矛盾／色覚多様性／ヒートマップの指標選択／2×2のしきい値の扱い、の5点）。

## 補足

- 第1段階だけでも投稿は成立する。PowerPoint化は「実務で使える」を示す第2幕として使える
- チャート形式は10個に固定する必要はないが、**多すぎると1枚あたりが小さくなり動画で潰れる**。
  8〜12が扱いやすい
- 「何が言えないか」を書かせるのが効く。褒め言葉だけのカードが並ぶと、
  選ぶ理由がなくなって試着室として機能しない
