# チャート試着室 — 配布用プロンプト

同じデータを10形式で描き分け、「誰に何を言いたいか」で1枚に絞り込むページを作らせる指示文。
第2段階として、選んだ1枚をPowerPointのネイティブチャートに起こす指示文も置いている。

このリポジトリの [`index.html`](./index.html) は、下記プロンプトで作れる完成形の一例。

---

## 第1段階 — 10形式を一気に描かせる

> 使い方: 末尾の「データ」を自分のものに差し替えて、まるごと貼る。

```text
あなたはデータビジュアライゼーションの設計者です。
渡すデータについて、考えられるチャート形式を10通り作り、1つのHTMLページに並べてください。
目的は「どのチャートで見せるべきか」を実物を見ながら選べるようにすることです。

## 作るもの

自己完結した1枚のHTMLファイル。外部CDNを使わず、CSSとJSはすべてインラインに書く
（オフラインで開けること）。チャートはライブラリを使わずSVGで描く。
コードは省略せず、10枚ぶんすべて書き切ること。
「同様に残りを実装」のようなコメントで置き換えないこと。

構成:
1. ヘッダー — データの一言説明と、全体で何が起きているかを1文
2. 目的セレクタ（後述。ここが本体）
3. 10枚のチャートをカードでグリッド配置
4. 「数値で見る」— 折りたたみの元データ表

各カードに入れるもの:
- チャート名（例: 構成比の変化）
- 形式名（例: 100%積み上げ）
- チャート本体
- その形式で「何が言えて、何が言えないか」を1文

## 10形式（この10個を必ず全部作る）

1.  折れ線 ............ 時系列の動き
2.  積み上げ棒 ........ 合計と構成の推移
3.  100%積み上げ ...... 構成比の変化
4.  ウォーターフォール .. 期首から期末への増減分解
5.  バブル ............ 規模 × 成長 × 収益性の3軸
6.  2×2マトリクス ..... ポジショニング・優先度
7.  ヒートマップ ....... 時期 × カテゴリの濃淡
8.  横棒ランキング ..... 現時点の大小
9.  スロープグラフ ..... 2時点間の変化と順位の入れ替わり
10. 小倍数 ............ カテゴリを並べて平等に比較

データの性質上どうしても成立しない形式があれば、無理に描かず
「このデータでは成立しない理由」をカードに書くこと。
軸を捏造して埋めないこと。

補足:
- ヒートマップは他の9枚と同じ指標である必要はない。積み上げ棒と内容が重複するなら、
  解約率・利益率など別の指標を採ってよい（そのぶんページ全体の情報量が増える）
- 2×2のしきい値は分析者が置く線なので、値を明示し、
  「データが決めた線ではない」ことをカードに書くこと

## 目的セレクタ（この機能が中心）

ページ上部に「誰に、何を言いたいですか」というボタンを4つ置く。
目的はデータの内容から自分で考えて設定する
（例: 役員に投資判断を迫る / 現場に危機感を伝える / 経営会議で現状報告する / 再編を提案する）。

押したときの挙動:
- 推奨する1枚以外のカードを不透明度0.24まで沈める（消さない。比較できることが大事）
- 推奨する1枚に枠線でスポットライトを当てる
- なぜその1枚なのかの理由を2文で表示する。理由には必ずデータ上の具体的な数字を含める
- 「すべて表示」で元に戻せる
- 切り替えは0.35秒のトランジション（動画で見せるため）

目的が変われば推奨も変わること。4つとも同じ答えになるなら、目的の設定を見直す。

## チャート品質のルール（必ず守る）

【色】
- 色はカテゴリ（実体）に紐づける。製品Aは10枚すべてで同じ色にする。
  チャートごとに色を振り直さない
- 系列は最大4つまで。5つ以上なら上位4つ +「その他」に畳む。
  ただしカテゴリが10を超えるときは、**畳むより単色で描く**方がよいことが多い
  （順位や面積が情報を持っており、色で分ける必要がない）。
  グルーピングを新たに作るなら、それが元データに無い解釈であることを明記する
- 濃淡（順序尺度）は1色の明暗だけで表す。虹色にしない
- 増減は青（増）と赤（減）、中間は無彩色
- 文字に系列色を使わない。ラベル・数値・凡例は本文色にし、
  識別は隣に置いた色マークが担う（薄い色は文字にすると読めない）
- 色覚多様性でも見分けられる組み合わせにする。赤×緑、オレンジ×黄、
  明度の近い同系色を隣り合わせにしない。識別を色だけに頼らせず、
  直接ラベルか凡例を必ず併置する

【マーク】
- 棒の太さは最大24px。バンドを埋め尽くさない
- 線は2px、マーカーは直径8px以上
- px指定は「設計サイズでの値」。SVGを設計サイズより拡大しないこと
  （viewBoxと同じ幅で max-width を掛ける）。伸縮させると24pxの棒が30pxに太り、
  8pxのマーカーが6pxに縮んで、指定が意味をなさなくなる
- 積み上げの各段の間、隣接する棒の間は、背景色の2pxの隙間で分ける（枠線で囲まない）
- グリッド線は1pxの実線で、背景から一段だけ濃い色。破線にしない
- 目盛りはキリのいい数字に丸める

【ラベル】
- すべての点に数値を書かない。端・極値・主役の系列だけに書く
- ラベルが重なるなら、ずらさずに諦めて凡例に任せる
  （ずらすと線から離れて、どの系列の値か分からなくなる）
- 凡例はページ上部に1つだけ置き、各カードには繰り返さない
  （10枚に同じ凡例が並ぶと場所を食い、動画では特に邪魔になる）
- 単独で見ても意味が通る必要があるチャートだけ、直接ラベルを添える

【やらないこと】
- 3D、影付き、グラデーション背景
- 2軸グラフ（左右で別スケール）。単位が違うなら2枚に分ける。
  例外はパレート図だけ（量の棒と累積%の線は2軸で描いてよい。
  片方に揃えると棒が潰れて読めなくなる）
- 円グラフを主役にする（構成比は100%積み上げか横棒で）
- 数値を全部書き込む

【検算】
- ウォーターフォールは、分解した各項の合計が期末の値に厳密に一致すること。
  一致しない分解は出さない
- 100%積み上げは各期の合計が100%になること
- すべてのチャートの数値が、末尾の元データ表と一致すること

【見た目】
- ダークモードに対応する。色はCSS変数で定義し、OSの設定
  （prefers-color-scheme）に追従する。手動のテーマ切替ボタンを付ける場合は、
  ボタンの選択がOS設定より優先されるようにする
- 日本語のWebフォントは読み込まない（重い）。システムフォントで、
  ウェイトと字送りで階層を作る
- 横スクロールを発生させない

## 出す前の自己チェック

以下を全部確認し、直してから出すこと。

1. 10枚すべてが最後まで書き切られているか。ブラウザで確認できる環境なら
   開いて描画とエラーを見る。できない環境なら、未定義の変数・閉じ忘れたタグ・
   書きかけのチャートがないかコードを読み直す
2. 同じカテゴリが全チャートで同じ色になっているか
3. ラベルが他の要素と重なっていないか
   （特に 2×2の象限名 / バブルのラベル / 折れ線の右端 の3か所）
4. ウォーターフォールの合計が期末の値と一致するか
5. 目的を切り替えたとき、推奨されるチャートが実際に変わるか
6. ダークモードで文字が読めるか
7. 各カードの「何が言えないか」が、そのチャートの実際の弱点を突いているか
   （褒め言葉だけになっていないか）
```

## 検証結果（2026-08-13）

まっさらなセッションに精密版を貼り、**別データ**（SaaSのプラン別ARR: 3年 × 4プラン、
契約社数・粗利率・解約率つき）で一発生成させた結果、自己チェック7項目すべてを満たした。

| 観点 | 結果 |
|---|---|
| 10形式すべて描画 | ○ 成立しない形式なし |
| カテゴリと色の固定 | ○ 10枚とも同じ色 |
| ラベル衝突 | ○ 0件（2×2の象限名・バブル・折れ線の右端とも） |
| ウォーターフォールの検算 | ○ 1,380 +340 +35 −90 −135 = 1,530 |
| 目的で推奨が変わる | ○ 4目的が4枚とも別（バブル / ヒートマップ / 積み上げ棒 / 滝） |
| ダークモード | ○ 単純反転ではなく暗い面用に色を作り直していた |
| 「何が言えないか」の質 | ◎ 下記のとおり実際の弱点を突いていた |

「言えないこと」の出力例（プロンプトの自己チェック7が最も効いた）:

> 100%積み上げ — 縦軸が常に100%なので全社ARRが増えたのか減ったのかは完全に消える。
> 全プランが半減しても、この絵はまったく同じ形になる。

> ヒートマップ — 色は順序しか表さないので「44%は28%の1.6倍」という量の差は読めず、
> ARRの規模が入らないぶん、小さい事業の悲鳴を実際より大きく見せてしまう。

> 小倍数 — 共通スケールの代償として Legacy 190→55（−71.1%）の急落がパネル下端で潰れる。
> 当事者にとっては事業消滅の3年間なのに、絵の上ではほぼ平らな線になってしまう。

指示していないのに足されたもの: テーマ切替ボタン、カード番号。

**この検証で見つかった不足は、上のプロンプトに反映済み**（凡例の重複／px指定とSVG伸縮の
矛盾／色覚多様性／ヒートマップの指標選択／2×2のしきい値の扱い、の5点）。

## 応用版 — データの形を診断してから選ばせる

精密版は「カテゴリ × 時間 × 加算できる量」に最適化してある。売上・利益・契約数はこの形だが、
利益率だけのデータや、時系列のないスナップショットでは、10形式のうち何枚かが前提から成立しない。

応用版は**先にデータを診断させ、成立する形式だけを20のメニューから選ばせる**。
落とした形式とその理由も申告させるので、「選ばなかったのか、思いつかなかったのか」が読み手に伝わる。

> こちらは単体で完結する。精密版と併用せず、これだけを貼ればよい。

```text

## 手順

### 手順1 — データを診断する（先にこれをやる）

次を判定し、ページ冒頭に「このデータをこう読みました」として明示する。

- 時間軸: あるか / 何時点か
- カテゴリ軸: いくつか / 第2のカテゴリ軸はあるか
- 測度: 何本か / それぞれ加算できるか（売上=できる、利益率・単価・シェア=できない）
- 正負が混ざるか

判定を間違えると以降が全部ずれるので、迷ったら「この列は加算できない」と
保守的に判定すること。

そのうえで、非加算の比率から加算可能な量を復元できないかを確認する。
比率にその分母を掛けると外延量に戻るので、パレート・ツリーマップなど
「加算可」を要求する形式が成立するようになる。
（例: 一人当たり売上 × 従業員数 = 部門売上）
復元した列は派生であることを明示し、元データの列と混同させないこと。

### 手順2 — 成立する形式を選ぶ

下のメニューから、手順1の診断で前提を満たすものを10個選ぶ。
上から順に採用するのではなく、「同じことしか言わない2枚」を避け、
違う角度が10通りそろうように選ぶ。
前提を満たす形式が10に満たないデータなら、無理に埋めず、
作れた枚数で止めて「なぜ10に届かないか」をページに書く。

［前提が緩い順］
横棒ランキング / ドットプロット / スロープ / パレート / ツリーマップ /
折れ線 / ヒストグラム / ブレット / 散布図 / ヒートマップ / 小倍数 /
面グラフ / ファネル / レンジプロット / バブル / 2×2マトリクス /
積み上げ棒 / 100%積み上げ / ウォーターフォール / コホート表

各形式が要求する前提:

| 形式 | 時間軸 | カテゴリ | 測度 | その他 |
|---|---|---|---|---|
| 横棒ランキング | 不要 | 2以上 | 1本 | 前提が最も緩い |
| ドットプロット | 不要 | 2以上 | 1本 | 非加算でも可 |
| レンジプロット | 不要 | 2以上 | 1本 | グループ内の幅（最小〜最大）を見せたいとき |
| 散布図 | 不要 | 点が多いほど良い | 2本 | |
| バブル | 不要 | 2以上 | 3本 | |
| 2×2マトリクス | 不要 | 2以上 | 2本 | しきい値の根拠が要る |
| ヒストグラム | 不要 | 不要 | 1本 | 標本が多いこと |
| パレート | 不要 | 5以上 | 1本 | 加算可 |
| ツリーマップ | 不要 | 5以上 | 1本 | 加算可 |
| ブレット | 不要 | 2以上 | 実績と目標 | |
| ファネル | 不要 | 段階 | 1本 | 単調減少すること |
| スロープ | 2時点 | 2以上 | 1本 | 非加算でも可 |
| 折れ線 | 3時点以上 | 1以上 | 1本 | |
| 小倍数 | 3時点以上 | 4以上 | 1本 | |
| 面グラフ | 3時点以上 | 1以上 | 1本 | 積み上げるなら加算可能なこと |
| ヒートマップ | 時間 or 第2カテゴリ | 2以上 | 1本 | |
| 積み上げ棒 | 2時点以上 | 2以上 | 1本 | 加算可能なこと |
| 100%積み上げ | 2時点以上 | 2以上 | 1本 | 加算可能なこと |
| ウォーターフォール | 2時点 | 2以上 | 1本 | 加算可能な分解ができること |
| コホート表 | 時間 × 開始時期 | — | 1本 | 開始時期ごとの追跡（残存率など）ができること |

軸を捏造して形式を埋めないこと。読み替えて成立させる場合は、
何をどう読み替えたかをカードに明記する。

### 手順3 — 落としたものを申告する

10個に入らなかった形式のうち、「一見できそうなのに前提を満たさないもの」を
3つまで挙げ、なぜ成立しないかを1行で書く。
（例: ウォーターフォール — 利益率は足し算できないため、増減の分解が定義できない）

これを書かないと、選ばなかったのか、思いつかなかったのかが読み手に伝わらない。

## 目的セレクタ

ページ上部に「誰に、何を言いたいですか」というボタンを4つ置く。

押したときの挙動:
- 推奨する1枚以外のカードを不透明度0.24まで沈める（消さない。比較できることが大事）
- 推奨する1枚に枠線でスポットライトを当てる
- なぜその1枚なのかの理由を2文で表示する。理由には必ずデータ上の具体的な数字を含める
- 「すべて表示」で元に戻せる
- 切り替えは0.35秒のトランジション

目的が変われば推奨も変わること。4つとも同じ答えになるなら、目的の設定を見直す。

## チャート品質のルール（必ず守る）

【色】
- 色はカテゴリ（実体）に紐づける。同じカテゴリは全チャートで同じ色にする。
  チャートごとに色を振り直さない
- 系列は最大4つまで。5つ以上なら上位4つ +「その他」に畳む
  （カテゴリを色で塗り分けない図では、この制限は適用しない）。
  カテゴリが10を超えるときは、畳むより単色で描く方がよいことが多い。
  グルーピングを新たに作るなら、それが元データに無い解釈であることを明記する
- 濃淡（順序尺度）は1色の明暗だけで表す。虹色にしない
- 増減は青（増）と赤（減）、中間は無彩色
- 文字に系列色を使わない。ラベル・数値・凡例は本文色にし、
  識別は隣に置いた色マークが担う（薄い色は文字にすると読めない）
- 色覚多様性でも見分けられる組み合わせにする。赤×緑、オレンジ×黄、
  明度の近い同系色を隣り合わせにしない

【マーク】
- 棒の太さは最大24px。バンドを埋め尽くさない
- 線は2px、マーカーは直径8px以上
- px指定は「設計サイズでの値」。SVGを設計サイズより拡大しないこと
  （viewBoxと同じ幅で max-width を掛ける）
- 積み上げの段の間、隣接する棒の間は、背景色の2pxの隙間で分ける（枠線で囲まない）
- グリッド線は1pxの実線で、背景から一段だけ濃い色。破線にしない
- 目盛りはキリのいい数字に丸める

【ラベル】
- すべての点に数値を書かない。端・極値・主役だけに書く
- ラベルが重なるなら、ずらさずに諦めて凡例に任せる
- 凡例はページ上部に1つだけ置き、各カードには繰り返さない

【やらないこと】
- 3D、影付き、グラデーション背景
- 2軸グラフ（左右で別スケール）。単位が違うなら2枚に分ける。
  例外はパレート図だけ（量の棒と累積%の線は2軸で描いてよい。
  片方に揃えると棒が潰れて読めなくなる）
- 円グラフを主役にする
- 数値を全部書き込む

【検算】
- 加算可能と判定した測度についてのみ、合計の整合を確認する
- すべてのチャートの数値が、末尾の元データ表と一致すること

【見た目】
- ダークモードに対応する。色はCSS変数で定義し、OSの設定
  （prefers-color-scheme）に追従する。手動のテーマ切替ボタンを付ける場合は、
  ボタンの選択がOS設定より優先されるようにする
- 日本語のWebフォントは読み込まない。システムフォントで階層を作る
- 横スクロールを発生させない

## 出す前の自己チェック

以下を全部確認し、直してから出すこと。

1. 10枚すべてが最後まで書き切られているか。ブラウザで確認できる環境なら
   開いて描画とエラーを見る。できない環境なら、未定義の変数・閉じ忘れたタグ・
   書きかけのチャートがないかコードを読み直す
2. 同じカテゴリが全チャートで同じ色になっているか
3. ラベルが他の要素と重なっていないか
   （象限名・バブルのラベル・線の右端が定番の衝突箇所）
4. 加算可能と判定した測度の合計が合っているか
5. 目的を切り替えたとき、推奨されるチャートが実際に変わるか
6. ダークモードで文字が読めるか
7. 各カードの「何が言えないか」が、そのチャートの実際の弱点を突いているか
   （褒め言葉だけになっていないか）
8. 手順1の診断と、実際に描いた10形式が矛盾していないか
   （「加算できない」と判定した測度で積み上げを描いていないか）
```

### つまずく典型パターン（このプロンプトが効く場面）

- **利益率・単価・シェアだけのデータ** — 足し算に意味がないので、積み上げ棒・100%積み上げ・
  ウォーターフォールの3枚が原理的に成立しない。ドットプロット・スロープ・散布図・
  レンジプロットが受け皿になる
- **時系列がない（スナップショットだけ）** — 折れ線・スロープ・小倍数・滝・ヒートマップの
  5枚が落ちる。横棒・パレート・ツリーマップ・散布図・2×2に寄せる
- **カテゴリが1つだけ** — 構成系が全滅。折れ線・ヒストグラム・ブレットに寄せる
- **カテゴリが20以上** — 「上位4＋その他」に畳むと情報が消える。
  パレート・ヒストグラム・散布図・ツリーマップの出番
- **測度が1本しかない** — バブルと2×2が作れない

### それでも向かないもの

- **自由記述のアンケート、インタビュー記録** — チャート以前に構造化が要る
- **1行しかないデータ** — 比較対象がないので、どの形式も成立しない
- **因果を主張したいとき** — 散布図は相関までしか示さない

## 補足

- 第1段階だけでも投稿は成立する。PowerPoint化は「実務で使える」を示す第2幕として使える
- チャート形式は10個に固定する必要はないが、**多すぎると1枚あたりが小さくなり動画で潰れる**。
  8〜12が扱いやすい
- 「何が言えないか」を書かせるのが効く。褒め言葉だけのカードが並ぶと、
  選ぶ理由がなくなって試着室として機能しない
