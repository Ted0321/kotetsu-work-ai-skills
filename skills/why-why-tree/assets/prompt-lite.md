# なぜなぜ分析プロンプト（凝縮版 / X配布用）

SKILL.md の分析プロトコルを、チャットAIへコピペ1発で使える形に凝縮したもの。
リプ欄配布用。HTMLツリー出力はエージェント型（SKILL.md＋assets）のみの機能。

---

```text
【なぜなぜ分析プロンプト】以下をすべてコピペし、最後の■問題に1行書いてください。

あなたはプロのコンサルタントとして、なぜなぜ分析を「型」で実行します。
木を一度に出さず、1階層ずつ「展開→検証→停止判定」を繰り返してください。

■手順
1. 問題の固定：曖昧な訴えを期間・件数・程度で定量化し、「あるべき／現状／ギャップ」を1行ずつ書く。
   ユーザーから事実・データが与えられていなければ「仮説モード」と宣言し、
   以後の原因はすべて検証前提の仮説として扱う（現場を知ったかぶりで断定しない）
2. なぜ①：分解の切り口を1行宣言してから、原因を2〜4個出す（切り口なしの思いつき列挙は禁止）
3. 各階層で、掘る前に全ノードを停止判定する：
   ● 対策可 …「誰が・何を・どう変えるか」を1文で書ける → 打ち手を添えて停止
   ◐ 要検証 … データや現場観察で確かめる粒度に達した → 検証方法を添えて停止
   ○ 所与 … 自分たちの裁量で変えられない（市況・法規制等） → 前提として停止
   △ 要調査 … 情報不足で仮説の域を出ない → 確認事項を添えて停止
   どれにも当たらなければ次の階層へ。「なぜ5回」は目安であって目的ではない
4. 続行ノードだけを次の階層へ展開し、毎回検証する：
   ・逆読み：「（子）。だから（親）」と読んで自然に通るか。中間の「なぜ」を挟めるなら飛躍→分割する
   ・言い換え禁止：子は親や既存ノードの同義文ではなく、新しい事実・機構を1つ含む
   ・主語と時制を明示する。「〜が徹底されていない」だけの主語なし文は禁止
   ・人を責めない：注意力・意識・やる気を原因にしない。
     人に見えたら「なぜその行動が仕組み上可能なのか」に言い換える
   ・兄弟監査：兄弟の粒度（抽象度・時間軸・主語の範囲）が揃っているか／重複がないか／
     子をすべて解消したら親は消えるか（消えないなら「その他（未特定）」を明示して隠さない）
5. 各階層の終わりに、木全体をマーク付きインデントで再掲する
   （例：├─ ● 遅延時のエスカレーション基準が未定義 → 打ち手: 遅延3日でPM報告を規定）
6. 全ノードが停止したら（安全弁：深さ7・合計30ノード上限）、最後に：
   ・全リーフ→問題まで「だから」で逆読みし、通らないリンクを修正する
   ・寄与度 × 制御可能性 × 実行容易性で「本命パス」を1本選び、選定理由を1文で言う
   ・「根本原因と次の一手」の表（型／原因／打ち手または検証方法）で締める

■問題：（ここに書く。例：直近4PJ中3PJで納期が1ヶ月以上遅延している）
```
