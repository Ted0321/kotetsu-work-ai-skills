### 本文（▼以降）

```text
▼仕組み

なぜなぜ分析は、慣れた人がやっても崩れます。人間がやりがちな失敗は4つあって、それぞれを防ぐ工夫をプロンプトの工程に入れました。

①問題設定が曖昧なまま掘り始める
「売上が落ちてる、なぜ？」で始めると、原因の解像度もそこ止まりになります。最初に期間・件数・程度で定量化して固定させる。「いつも遅れる」→「直近4PJ中3PJで納期1ヶ月超過」。特に程度が決まらないと、運用レベルの原因を探すのか構造レベルを探すのかも決まりません。

②粒度がバラバラでMECEにならない
「組織文化」と「先週のメール誤送信」が同じ階層に並ぶやつです。ポイントは、「MECEにして」と命令してもMECEにはならないこと。子を出す前に「この原因を何の軸で分解するか」を毎回宣言させると、兄弟が自動的に同じ軸に乗ります。MECEは指示ではなく結果です。出したあとも兄弟単位で、粒度・重複・十分性（子を全部潰したら親は消えるか）をその場で確認させます。

③掘るほど抽象的になり、そもそも論で終わる
「なぜ？」は問うたびに一段抽象へ上がる性質があるので、放っておけば必ず上に流れます。だから掘る前に「ここで止めるか」を判定させました。打ち手が1文で書けたらそこが底。深さを成り行きではなく、打ち手から逆算して決めます。

④原因が出揃った後、どれも正しく見えて絞れない
ここを感覚でやると会議が終わりません。インパクト×実行容易性×波及（他の枝にも効くか）の3軸で採点させて、優先順位表を出させます。インパクトだけで選ぶと「正しいが動かない打ち手」、実行容易性だけだと「動くが効かない打ち手」になるので3軸。確かめないと動けないものは「要検証」として、検証方法とセットで分けて残します。

▼使い方
リプ欄のプロンプトをコピペして、末尾の■問題に1行書くだけ。Claude / ChatGPT / Gemini いずれでも動きます。
```

## 事実確認メモ

- 本文の4項目は、プロンプトのトップレベル4工程とそのまま対応する（読者が開いて確認できる）:
  ①定量で固定 → Phase 0 ／ ②軸を宣言してから割る → Step 2＋Step 3 ／
  ③打ち手基準で止める → Step 1 停止ゲート ／ ④軸で採点して絞る → Phase F
- **「AIの癖」ではなく「人間がやりがちな失敗」として書く。** これがコンセプトの芯
- 「1本の枝だけ深く掘って他が浅い」は事実として不正確（AIはむしろ網羅的に掘る）。
  v0.6まで誤って記載していたため削除し、「①問題設定が曖昧なまま掘り始める」に差し替え
- 「そもそも経営が」という具体語は使わない。「そもそも論で終わる」で十分伝わる
- まとめの造語（掘る×検査／疑う力）は不採用。症状と対策を直接並べる
- 優先順位の3軸から制御可能性を外しているのは、停止ゲートの○所与で既に除外しているため
- 本文は「プロンプト」として訴求（スキル/インストールの語は本文から排除）
