## 本文

```text
なぜなぜ分析を実行できるskillsを作ったのでシェアします。問題を投げるだけで、AIが根本原因までロジックツリーで掘り下げ、打ち手までまとめた1枚のHTML資料が出てきます。
実はなぜなぜ分析、ちゃんとやるのは意外と難しくてコツがいる。コンサルの腕の見せ所でもあるその勘所を、プロンプトの構造に落とし込みました。

インストール方法は、
Claude Code（デスクトップ版OK）にこの1行を貼るだけ。

「github.com/Ted0321/kotetsu-work-ai-skills の skills/why-why-tree を ~/.claude/skills/ にインストールして」

・問題文1つでOK。ツリー＋根本原因＋打ち手の一覧表がHTML1枚で出ます（A4印刷OK）
・根本原因には打ち手が、確かめが必要な仮説には検証方法が必ず付きます
・最後に「最も効く1本道」を1本選んで強調します
・CLI派は npx skills add Ted0321/kotetsu-work-ai-skills@why-why-tree
・ChatGPT派はSKILL.mdのコピペでも動きます（テキスト木＋Mermaidで出力）

▼仕組み

なぜなぜ分析、手順はシンプルなのに、ちゃんとやると奥が深い。つまずきどころは3つで、このスキルはそれぞれに対応する型をプロンプトで強制します。

①どこまで掘ればいいか分からない（浅すぎる・掘りすぎる）
→ 掘る前に毎回「停止判定」を入れました。対策が1文で書けたらそこが底。「なぜ5回」という回数ではなく、打ち手から逆算して止まります。

②階層ごとの論理がズレる（飛躍・言い換えが混ざる）
→ ツリーの一括生成を禁止し、1階層ずつ「（子）。だから（親）」と逆読みして通るかを検証します。兄弟ノードの粒度（抽象度・時間軸・主語）も毎階層で揃えます。

③次のアクションに繋がらない
→ 「担当者の注意力不足」のような精神論を原因にすることを禁止し、仕組みの言葉で書かせます。だから根本原因がそのまま打ち手になります。知り得ない現場の事情は断定せず、「要検証」として検証方法とセットで残します。

この3つは、コンサルが現場でなぜなぜ分析を回すときの勘所そのものです。言葉で注意させるのではなく、手順と判定条件としてプロンプトに埋め込みました。

▼最後に
SKILL.mdは全文公開しています。ポイントは「なぜを繰り返せ」と指示しないこと。掘り方のルールと止まる条件を渡すと、AIは正しい深さで止まって、打ち手に着地します。改善PRも歓迎です。
```

## 事実確認メモ（本文の主張とスキル仕様の対応）

- 自然言語インストール1行 → skills/why-why-tree/ 一式（SKILL.md＋assets）が入る前提。HTMLツリー出力にはassetsのテンプレートが必要
- 「ChatGPT派はコピペでも動く」→ 出力はテキスト木＋Mermaid＋対策表（HTMLツリーはエージェント型のみ）。本文でも括弧書きで明示済み
- ①=停止ゲート（●対策可で停止・深さ7上限）、②=BFS階層ループ＋逆読み＋兄弟監査、③=R6仕組み語り＋●打ち手必須＋◐検証方法必須、にそれぞれ対応
- html-report-design投稿にあった「コピペ用凝縮版」は本スキルには未収録。作るなら `assets/prompt-lite.md` を別途用意する（要判断）
