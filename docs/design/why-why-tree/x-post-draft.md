# why-why-tree — X投稿ドラフト v0.1

形式は html-report-design 投稿と同型（フック問題提起 → 導入1行 → 箇条書き → ▼仕組み → ▼最後に）。

## 本文

```text
AIのなぜなぜ分析、3回目から「言い換え」が始まる問題。これを終わらせるために、なぜなぜ分析を「コンサルの型」で実行して根本原因まで掘り切るskillsを作ったのでシェアします。

これを入れておけば、問題を投げるだけで、ロジックツリーを1階層ずつ検証しながら育てて、対策が打てる根本原因まで分解。最後は1枚のHTML資料に仕上がります。

インストール方法は、
Claude Code（デスクトップ版OK）にこの1行を貼るだけ。

「github.com/Ted0321/kotetsu-work-ai-skills の skills/why-why-tree を ~/.claude/skills/ にインストールして」

・「なぜ5回」ではなく、展開→検証→停止判定の階層ループで掘ります
・全リーフに型が付きます: ●対策可（打ち手1文つき）／◐要検証（検証方法つき）
・最後に本命パス（最も効く1本道）を1本だけ選んで強調
・出力はA4印刷でそのまま配布できるHTMLツリー＋対策表
・CLI派は npx skills add Ted0321/kotetsu-work-ai-skills@why-why-tree
・ChatGPT派はSKILL.mdのコピペでも動きます（テキスト木＋Mermaidで出力）

▼仕組み

なぜなぜ分析が壊れる原因は、AIが「回数」で掘ること。プロは「型」で掘ります。
このスキルは木の一括生成を禁止し、1階層ずつ検証を強制します。

・子を書く前に「切り口」を宣言させる（思いつき列挙の禁止）
・「（子）。だから（親）」の逆読みで、飛躍と言い換えを検出
・兄弟ノードの粒度（抽象度・時間軸・主語）を毎階層で監査
・掘る前に停止判定。対策が1文で書けたらそこが底——「なぜ5回」は目安であって目的ではない
・「担当者の注意力不足」のような人責め原因は、仕組みの言葉に言い換えさせる

現場の事実を渡さなければ「仮説モード」を宣言し、断定せずに検証タスクとして木に残します。事実を貼るほど木は強くなります。

▼最後に
SKILL.mdは全文公開しています。読むと分かるのですが、ポイントは「なぜを繰り返せ」と指示しないこと。展開のルールと止まる条件を渡すと、AIは正しい深さで止まります。改善PRも歓迎です。
```

## 事実確認メモ（本文の主張とスキル仕様の対応）

- 自然言語インストール1行 → skills/why-why-tree/ 一式（SKILL.md＋assets）が入る前提。HTMLツリー出力にはassetsのテンプレートが必要
- 「ChatGPT派はコピペでも動く」→ 出力はテキスト木＋Mermaid＋対策表（HTMLツリーはエージェント型のみ）。本文でも括弧書きで明示済み
- html-report-design投稿にあった「コピペ用凝縮版」は本スキルには未収録。作るなら `assets/prompt-lite.md` を別途用意する（要判断）
