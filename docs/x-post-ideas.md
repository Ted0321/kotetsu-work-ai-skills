# X投稿ネタ帳

Tips系（実用性 × 動画映え）投稿のネタ台帳。スキル公開の計画は [ROADMAP.md](../ROADMAP.md)、投稿の型は [templates/thin_drop_x_post.md](../templates/thin_drop_x_post.md) を参照。

## 判断基準（バズの共通因子）

過去バズ4本（セッション自動リネーム / サブエージェント可視化 / マッキンゼー風スライド / ロジックツリー）に共通する3段構造。

1. **動画フック** — 動画・スクショ1枚で価値が伝わる（読まなくてもわかる）
2. **あるあるペイン** — 多くの人が毎日困っていることを解決する
3. **コピペ再現性** — 指示文をそのまま真似できる → 保存・ブクマで伸びる

3つ全部が立つネタを優先。②③だけのネタは面白み・意外性で①を代替できるかを見る。

## シリーズ構成

ネタは3系統で束ね、同じフック構造で連打できる編集資産として扱う。

| 系統 | 束ね方 | 魅せ方 | 系譜 |
|---|---|---|---|
| **A** | コンサル図解をAIで | 成果物の見栄え | マッキンゼー風スライド／ロジックツリー |
| **B** | コンサルは先に書く | 逆張りの意外性 | 事前議事録で発見した鉱脈 |
| **C** | Claude Codeを飼い慣らす | 挙動の可愛さ・便利さ | セッションリネーム／サブエージェント可視化 |
| **D** | 第二候補（保留） | — | — |

★＝採用（次に作る）。IDは固定、欠番は作らない。

## 採用ネタの詳細

### A-1. コンサル風チャート生成

- **ペイン**: バブルチャートやウォーターフォールを手作業で作るのは苦行。作れること自体が属人スキル化している
- **切り口**: 「バブルチャート、まだ手で作ってますか」「コンサル1年目が3時間かける図、AIなら1分です」
- **配布物**: チャート形式ごとの指示プロンプト（データの渡し方＋デザイン指定）
- **連載化**: バブル（ポジショニング）／ウォーターフォール（差異分解）／2×2（優先度）／ハーベイボール（比較評価）／メコ（市場規模×シェア）／トルネード（感度）
- **制作メモ**: HTML/SVGで描かせて画面録画するか、pptx生成まで見せるか。まず1形式で反応を見る。初回はA-4（試着室）が有力

### A-2. カッコいいHTML出力

- **ペイン**: AIにHTMLを作らせると素朴でダサい。スライドの代替にしたいのにあと一歩足りない
- **切り口**: 「報告、まだスライドですか。URLを1つ送るだけにしました」「AIのHTMLがダサい人、この一文が足りません」
- **配布物**: デザイン指示のコピペプロンプト（配色・余白・フォント・アニメーションの縛り方）
- **連動**: A-1と地続き。チャート単品→動くHTML報告書の順で出すと文脈がつながる。**A-8のデモがそのまま実弾になる**

### A-3. なぜなぜ分析スキル（育つロジックツリー）

- **ペイン**: なぜなぜ分析は形骸化しがち（粒度バラバラ／人のせいで終わる／浅すぎ・掘りすぎ）。単に「なぜ」を繰り返させるだけでは使い物にならない
- **設計要件（品質の生命線）**:
  1. **階層ルール**: 各階層のMECE感・粒度を揃える。1歩の掘り下げ幅を制御（飛躍しない・細かすぎない）
  2. **停止条件**: 具体的アクションに落とせる／検証可能なレベルまで細分化されたら止める
  3. **コンサル勘所**: プロがなぜなぜ分析を行う際の作法をAIが理解した上で実行する
- **系譜**: 過去バズ「ロジックツリー」の正当進化 × スキル配布導線
- **ステータス**: 別セッションで設計思想とアウトプットイメージを検討中

### B-1. 事前議事録

- **ペイン**: ゴールが曖昧なまま会議が始まり、何も決まらずに終わる
- **切り口**: 「デキるコンサルは、会議の前に議事録を書きます」「明日の会議の議事録、もう書き終わりました」
- **配布物**: 決定事項（仮）／想定論点／想定される反論／持ち帰り事項、を先に書かせるプロンプト
- **連動**: issue-structuring スキルへの導線。B-10（答え合わせ）を続編に温存

## A-4 チャート試着室 — 実装ログ（2026-08-13）

デモ実装済み: [`demos/chart-fitting-room/`](../demos/chart-fitting-room/) — HTML（10形式一括）＋ `to-pptx.js`（選んだ1枚をスライド化）

**2段構成**（本人の構想どおり成立することを実装で確認）

1. **HTMLで10形式を一気に描く** — 折れ線／積み上げ棒／100%積み上げ／ウォーターフォール／バブル／2×2マトリクス／ヒートマップ／横棒ランキング／スロープグラフ／小倍数
2. **選んだ1枚をPowerPointに起こす** — 画像貼り付けではなく `addChart()` の**ネイティブチャート**。PowerPoint側で数値も色も編集できる

**仕掛け（ここが単なる「10個作った」との差）**

「誰に何を言いたいか」を選ぶと9枚が沈み、1枚だけが残って理由が出る。**目的を変えると残る1枚が変わる**のが動画のオチ。

| 目的 | 残る1枚 | 理由 |
|---|---|---|
| 役員に投資判断を迫る | バブル | 規模・成長・利益率が一度に乗る |
| 現場に危機感を伝える | スロープグラフ | 落差が最も残酷に見える |
| 経営会議で現状報告する | ウォーターフォール | 「横ばい」の中身を説明できる |
| 事業部の再編を提案する | 2×2マトリクス | 撤退と投資の線引きを1枚で示せる |

**題材の設計**: 全社売上は3年で+5%だが、中身は主力X（−19%）の崩れを新規Y（+367%）が埋めている。**同じデータが「順調」にも「危機」にも見える**ため、チャート選択の重みがそのまま伝わる。

**技術メモ**
- 4製品の色は8スロットの全4色組（70通り）を総当たりし、散布・小倍数系で要求される全ペア判定を**ライト/ダーク両モードで通る**組（blue/yellow/magenta/green）を選定
- 折れ線の端ラベルは4本中3本が衝突するため意図的に不使用（ずらすと線から離れて誤読を招く）。凡例に識別を持たせた。これは折れ線の弱点そのもので、試着室で見せたい教訓と一致する
- PowerPointに滝グラフは無いため、透明の土台を積んで再現（土台＋合計＋増益＋減益の4系列を積み上げ）
- 生成物は `validate.py` PASS、python-pptxで3枚・ネイティブチャート2点・全系列の数値を確認済み。**画像での目視QAはこの環境に `libreoffice-impress` が無いため未実施**（PowerPointでの確認が必要）

**残タスク**: 撮影用の配布プロンプト（自分のデータで再現するための指示文）

## A-8 感度シミュレーター — 検討ログ（2026-08-13）

デモ実装済み: [`demos/price-sensitivity/index.html`](../demos/price-sensitivity/index.html)

つまみ4つ（値上げ率・価格弾力性・変動費・固定費）を動かすと、営業利益ブリッジ・感度カーブ・トルネード図が同時更新される1枚もののHTML。利益ブリッジは価格/数量/変動費/固定費の4効果に厳密分解（全パラメータ空間で残差1.2e-7円まで整合を検算済み）。配色は増益=青/減益=赤の発散ペアで、CVD分離とコントラストを検証済み。

**用途の再定義（ここが本質）**

刺さる相手は「Excelで試算表を作っている人」全員。ペインは一点。

> 会議で「じゃあ単価を5%下げたら?」と聞かれて **「持ち帰ります」** と言う瞬間

試算表は作った本人しか動かせないので、会議に持ち込んだ瞬間に静止画になる。楽観/標準/悲観の3パターンを貼っても、聞かれるのは決まって4つ目のパターン。しかも意思決定者が本当に知りたいのは「どの数字が正しいか」ではなく、**どこまで耐えられるか（損益分岐）** と **どれが一番効くか（感度）** の2つで、3パターン表はどちらにも答えられない。

**「Excelでもできるのでは」への先回り**: できるが、データテーブル＋ゴールシークを組んで見栄えを整えると30分〜1時間。しかも他人に触らせられない（壊れる・配れない）。Claudeなら1分、URLで配れて、誰が触っても壊れない。

**刺さる人と場面**

| 誰 | 会議で飛んでくる一言 |
|---|---|
| 営業・営業企画 | 「この値引き、どこまでならOK?」 |
| 経営企画・事業企画 | 「この新規事業、何年で黒字化する?」 |
| 商品企画・マーケ | 「販促費をあと500万足したら回収できる?」 |
| 人事・現場マネージャー | 「1人増やして、元は取れるの?」 |
| 中小企業の経営者 | 「原材料が上がった。どこを触れば持ちこたえる?」 |

**X向けの題材**: 現行デモは「値上げ・弾力性」でコンサル寄りすぎる。**「値引き稟議」に差し替える**のが最善（対象者が桁違いに多く、専門用語が要らない）。次点は採用の投資回収。訴求は「『持ち帰って再計算します』を、会議から消す方法」。

**Claudeで広げる5段**

1. Excelを渡すだけ → 変数を読み取ってシミュレーター化（心理的ハードル最小）
2. 変数の設計から相談 → 「何を動かせる変数と見なすか」はコンサルの勘所そのもの
3. 逆算（ゴールシーク）→ 「利益150百万にするには?」に実現可能な組み合わせを複数＋実行難易度まで評価
4. 数字から示唆を書かせる → research-to-insight と同じ構造
5. **会議中にその場で作り替える** ← 本命。「弾力性じゃなく競合追随率で見せて」→30秒で作り替え。**Claude Codeでしか成立せず、動画としても最強**

**次の一手（保留中）**: (a) 値引き稟議版のデモを作る（入口を広く）／(b) 第5段「会議中に作り替える」の実演デモ（意外性が最大）。二段構えが強い。
