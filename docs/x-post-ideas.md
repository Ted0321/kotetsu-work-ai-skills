# X投稿ネタ帳

Tips系（実用性 × 動画映え）投稿のネタストック。スキル公開の計画は [ROADMAP.md](../ROADMAP.md)、投稿の型は [templates/thin_drop_x_post.md](../templates/thin_drop_x_post.md) を参照。

## 判断基準（バズの共通因子）

過去バズ4本（セッション自動リネーム / サブエージェント可視化 / マッキンゼー風スライド / ロジックツリー）に共通する3段構造。

1. **動画フック** — 動画・スクショ1枚で価値が伝わる（読まなくてもわかる）
2. **あるあるペイン** — 多くの人が毎日困っていることを解決する
3. **コピペ再現性** — 指示文をそのまま真似できる → 保存・ブクマで伸びる

3つ全部が立つネタを優先。②③だけのネタは面白み・意外性で①を代替できるかを見る。

## シリーズ構成

ネタは3系統で束ね、同じフック構造で連打できる編集資産として扱う。

- **A「コンサル図解をAIで」** — 成果物の見栄えで魅せる。マッキンゼー風スライド・ロジックツリーの系譜
- **B「コンサルは先に書く」** — 後で書くはずのものを先に書く逆張り実技。意外性で魅せる。事前議事録で発見した鉱脈
- **C「Claude Codeを飼い慣らす」** — セッションリネーム・サブエージェント可視化の系譜

## 採用（次に作る候補）

### 1. コンサル風チャートをAIでかっこよく出力する（バブルチャート等）〔A〕 — 2026-08-06

- **一言**: マッキンゼー風スライドの続編。「コンサルしか作らない図」をAIに描かせる
- **ペイン**: バブルチャートやウォーターフォールをPowerPointで手作業で作るのは苦行。作れること自体が属人スキル化している
- **動画映え**: ◎ 完成チャートのインパクト＋生成される過程。Before（生データ）→After（チャート）
- **切り口コピー案**: 「バブルチャート、まだ手で作ってますか」「コンサル1年目が3時間かける図、AIなら1分です」
- **配布物**: チャート形式ごとの指示プロンプト（データの渡し方＋デザイン指定）
- **展開（連載化）**: 1形式=1投稿で連打できる
  - バブルチャート（ポジショニングマップ）
  - ウォーターフォール（差異分解）
  - 2×2マトリクス（優先度整理）
  - ハーベイボール（比較評価表）
  - メコチャート（市場規模×シェア）
  - トルネード図（感度分析）
- **制作メモ**: HTML/SVGで描かせて画面録画するか、pptx生成まで見せるか。まず1形式で反応を見る
- **ステータス**: ネタ

### 2. HTMLをカッコよく出力する方法 〔A〕 — 2026-08-06

- **一言**: AIの出力を「そのまま人に見せられる」デザインのHTMLにする指示のコツ
- **ペイン**: AIにHTMLを作らせると素朴でダサいものが出てくる。スライド作成の代替にしたいのにあと一歩足りない
- **動画映え**: ◎ グラフがアニメーションで立ち上がる／スクロール・ホバーで動くダッシュボードの画面録画
- **切り口コピー案**: 「報告、まだスライドですか。URLを1つ送るだけにしました」「AIのHTMLがダサい人、この一文が足りません」
- **配布物**: デザイン指示のコピペプロンプト（配色・余白・フォント・アニメーションの縛り方）
- **連動**: ネタ1（チャート）と地続き。チャート単品→動くHTML報告書、の順で出すと文脈がつながる
- **ステータス**: ネタ

### 3. 会議の前に議事録を書かせる（事前議事録）〔B〕 — 2026-08-06

- **一言**: 会議の"あと"に書くはずの議事録を、AIに"先に"書かせる。仮説ドリブンの会議設計というコンサルの実技をAIでやる
- **ペイン**: ゴールが曖昧なまま会議が始まり、何も決まらずに終わる
- **面白み・意外性**: ◎ 「議事録は会議の前に書くもの」という逆張りの一言がそのままフックになる
- **動画映え**: △ テキスト成果物なので弱め。意外性で勝負。事前議事録→実際の会議→答え合わせ、の構成にすればストーリーで見せられる
- **切り口コピー案**: 「デキるコンサルは、会議の前に議事録を書きます」「明日の会議の議事録、もう書き終わりました」
- **配布物**: 事前議事録プロンプト（決定事項（仮）／想定論点／想定される反論／持ち帰り事項、を先に書かせる）
- **連動**: issue-structuring スキルへの導線に使える
- **ステータス**: ネタ

### 4. なぜなぜ分析スキル（育つロジックツリー）〔A〕 — 2026-08-09追加

- **一言**: なぜなぜ分析をAIが深掘りし、その過程がロジックツリー形式で構築・成長していく。スキル化して配布
- **ペイン**: なぜなぜ分析は形骸化しがち（粒度バラバラ／人のせいで終わる／浅すぎ・掘りすぎ）。単に「なぜ」を繰り返させるだけでは使い物にならない
- **動画映え**: ◎ なぜを掘るたびにツリーが枝を伸ばして育つ過程を見せる（ブレスト案「育つロジックツリー」を統合）
- **設計要件（品質の生命線）**:
  1. **階層ルール**: 各階層のMECE感・粒度を揃える。1歩の掘り下げ幅を制御（飛躍しない・細かすぎない）
  2. **停止条件**: 具体的アクションに落とせる／検証可能なレベルまで細分化されたら止める
  3. **コンサル勘所**: プロがなぜなぜ分析を行う際の作法をAIが理解した上で実行する
- **系譜**: 過去バズ「ロジックツリー」の正当進化 × スキル配布導線
- **ステータス**: 設計検討中（別セッションで設計思想とアウトプットイメージを固める）

## 候補（未選別） — 2026-08-10整理

### シリーズA: コンサル図解をAIで

- **チャート試着室**: 1つのデータから10形式のチャートを一括生成し、AIに「経営報告ならこの1枚」と選ばせる。「グラフ選びで迷う人へ。全部作らせて、選ばせればいい」。**採用1の初回投稿として推奨**（1動画の情報量が多く保存されやすい）
- **スライド赤ペン添削**: スライドのスクショに赤入れコメント→コンサル風の修正版を再生成。Before/Afterの王道。「マネージャーの赤ペン、AIで再現できます」。**deliverable-review公開（8/8）直後の追い風があり優先度高**
- **決算資料→コンサルチャート1枚**: 決算短信PDF→増減益ウォーターフォール＋セグメントバブル。「決算短信、読むのやめました。描かせてます」。company-deep-dive連動
- **ポンチ絵→スライド清書**: 手書きメモの写真→完成スライド。「コンサル上司が部下に渡す『ポンチ絵』、AIに渡せば清書までやってくれます」（旧ストック「手書き→構造化」を統合）

### シリーズB: コンサルは先に書く

- **プレモータム**: 「本プロジェクトは失敗に終わった。原因は3つ——」という報告書を開始前に書かせる。「プロジェクトを始める前に、炎上の報告書を書かせています」。事前議事録の姉妹編
- **想定問答の鬼**: 資料を貼ると役員の意地悪質問20連発＋模範回答。「役員会の前日、コンサルは想定問答を作ります。AIなら5分です」。ストックのAI会議室と組み合わせ可
- **Day1仮説**: 調べる前に答えを書く。「新規案件で最初にやるのはリサーチではありません」。**research-to-insight公開（8/22）との連動枠**
- **空パック**: タイトル＋メッセージラインだけの骨子デッキを先に作る。「デキるコンサルは、いきなりスライドを作りません」。A×Bの交差点
- **So What?詰めモード**: 各ページにAIが「だから何?」を3回聞き、メッセージが研ぎ澄まされる過程を見せる
- **事前議事録の答え合わせ**: 実際の議事録とdiffを取り「想定通り3件/想定外2件」と採点。採用3がバズった後の続編として温存
