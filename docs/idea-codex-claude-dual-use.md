# Codex × Claude 二刀流の悩みマップとX投稿ネタ

CodexとClaude Codeを併用する人（二刀流）特有の悩みを分解し、解決の型・X投稿ネタ・スキル化候補に落とすための作業メモ。

## 結論（1行）

二刀流の悩みの根っこは1つ。**作業の記録とルールが、各ツールの中に閉じていること。**
だから解決の原則も1つ。**記録・ルール・タスクIDをツールの外（リポジトリ側・人間側）に出す。**

「どっちに何を頼んだか分からない」は記憶力の問題ではなく、置き場所の設計の問題。
セッション履歴はClaudeは `~/.claude/projects/`、Codexは `~/.codex/sessions/` と別々に積まれ、
さらにWeb版・IDE拡張で「面」が増える。ツール内の履歴を追いかける限り、この分断は解けない。

## 1. 悩みマップ（4層×12個）

### 層1: 記録・追跡 — 本丸

| # | 悩み | 具体 |
|---|---|---|
| 1-1 | タスク行方不明 | 「この修正どっちに頼んだっけ」。`claude --resume` と `codex resume` の一覧を両方開いて探す。Web版・IDE拡張も含めるとセッションの置き場が4面以上ある |
| 1-2 | 履歴の分断 | 「今週AIに何をやらせたか」が出せない。ログ形式が別、ブランチ接頭辞が別（`claude/` と `codex/`）、コミットの署名も別。バグの犯人捜し（どっちが入れた変更か）も難しい |
| 1-3 | 再開の摩擦 | 作業のつづきをやるには「どっちのツールの文脈にあるか」を先に思い出す必要がある。文脈はツール間で共有されないので、途中乗り換えは実質やり直し |

### 層2: 設定・資産の二重管理

| # | 悩み | 具体 |
|---|---|---|
| 2-1 | メモリのドリフト | CLAUDE.md と AGENTS.md を別々に育てると中身がズレて、同じリポジトリで2体が違うルールで動く |
| 2-2 | スキルの二重導入 | `.claude/skills/` と `.agents/skills/` に同じものを2回入れる。片方だけ更新して挙動が割れる |
| 2-3 | MCPの二重設定 | `.mcp.json` と `config.toml` に同じサーバーを2回書き、認証も2回。バージョンもズレる |

### 層3: 運用中の事故・干渉

| # | 悩み | 具体 |
|---|---|---|
| 3-1 | 同一作業ツリー衝突 | 2体を同じチェックアウトに入れて同時編集・lockファイル・devサーバーのポートが衝突 |
| 3-2 | モード誤認 | plan mode / read-only、承認モードの意味がツールで違う。Claudeのつもりでスラッシュコマンドを空振りし、Codexのつもりで全権を渡す |
| 3-3 | コードの方言 | コミット文体・コメント量・命名の癖が2流派になり、レビュー観点（各モデルの死角）も2セット必要になる |

### 層4: 判断・頭の使い方

| # | 悩み | 具体 |
|---|---|---|
| 4-1 | ルーティング迷い | 毎回「これどっちに投げるか」を考える。切り替えの意思決定コストが積もる |
| 4-2 | クォータやりくり | 5時間枠・週次上限が2系統。枠の都合で途中乗り換えが起き、それが層1を悪化させる |
| 4-3 | 評価が印象論 | 「Codexの方が○○に強い気がする」が検証できない。記録が無いから使い分けが上達しない |

### 因果ループ（層1を最初に解くべき理由）

```text
クォータ切れ(4-2) → 途中乗り換え → 記録の分断(1-1, 1-2) → 使い分けの根拠が残らない(4-3)
→ 毎回迷う(4-1) → また場当たりで乗り換える → …
```

分断の起点は層1。ここに台帳を置くと、4-1と4-3も自動的に解け始める。

## 2. 解決の型（今日できる順）

| # | 型 | 内容 | 解く悩み |
|---|---|---|---|
| A | 作業台帳 | リポジトリ直下に `AI_WORKLOG.md`。開始時に1行追記・終了時に更新を両エージェントに義務付け | 1-1, 1-2 |
| B | ID発番は人間 | タスクIDを人間が振る（日付+連番で十分）。ブランチ・台帳・コミットに同じIDを通す | 1-1, 1-2 |
| C | コミットtrailer | `Agent: codex` / `Agent: claude` と `Task: 0803-1` を必ず付けさせる。git logがそのまま合同日報になる | 1-2, 4-3 |
| D | 引き継ぎ書 | 乗り換え時は今のエージェントに `HANDOFF.md`（目的/済/未/ハマり/次の一手/確認方法）を書かせてから移る | 1-3, 4-2 |
| E | メモリ一元化 | AGENTS.md を正とし、CLAUDE.md は `@AGENTS.md` の1行だけにする。共通規約はAGENTS.mdの「エージェント共通規約」節に書く（1か所に書けば2体に効く） | 2-1, 2-2 |
| F | worktree分離 | 1エージェント=1worktree。devサーバーのポートも固定割当 | 3-1 |
| G | ルーティング3行 | 自分の決め打ち表を作って迷いを消す。台帳の結果で月1回見直す | 4-1, 4-3 |
| H | 週次AI日報 | 2ツールのセッションログ+git logを束ねて「今週AIにやらせたこと」を自動生成（将来のスキル化候補） | 1-2, 4-3 |

### A+B+C: 共通規約コピペ（フラッグシップ）

AGENTS.md（とCLAUDE.mdの `@AGENTS.md` 経由）に貼る5行。これだけで「どっちに頼んだっけ」が消える。

```markdown
## エージェント共通規約（Codex / Claude 共通）
- 作業開始時: リポジトリ直下の AI_WORKLOG.md の先頭に1行追記する
  形式: `- [ ] 0803-1 | codex | ブランチ名 | 依頼の一言 | 開始 08/03 14:00`
- 作業終了時: 自分の行を更新する（済なら [x] と結果を一言。未完なら「次の一手」を書く）
- コミットには trailer `Task: 0803-1` `Agent: codex` を付ける
- タスクIDは人間の指示に無ければ「日付+連番」で自分で振り、最初の返答で宣言する
```

合同日報の出し方（例）:

```bash
git log --since='1 week ago' --date=short \
  --format='%ad %h %(trailers:key=Agent,valueonly,separator=) %s'
```

注意: `separator=` は省略不可。無いとtrailer値の後ろに改行が入り1行1コミットの表が崩れる（git 2.43で実測）。

### D: 引き継ぎ書テンプレ（乗り換え5分ルール）

クォータ切れ・得意分野での乗り換え時に、離脱側へ最後に1回だけ依頼する。

```text
HANDOFF.md を書いて。項目は6つ:
1. 目的（このタスクは何ができたら終わりか）
2. 完了したこと（ファイル名つき）
3. 未完のこと（残作業を箇条書き）
4. ハマりどころ（試して駄目だった案と理由）
5. 次の一手（最初にやるべき1つ）
6. 確認方法（何を実行すれば動作確認できるか）
```

受け側の最初の指示は「HANDOFF.md を読んでから始めて」の1行。

### E: メモリ一元化の注意（Windows）

シンボリックリンクは管理者権限や開発者モードが要るので、CLAUDE.md に
`@AGENTS.md` と書くインポート方式が安全。リンクより壊れにくい。

### G: ルーティング3行（例。正解ではなく、台帳で自分の実測に更新していく）

```text
- 設計相談・仕様の壁打ち・長丁場のリファクタ → Claude
- 単発の修正・テスト生成・書き捨てスクリプト → Codex
- 失敗したくない重要変更 → 両方に同じIDで投げて突き合わせ（台帳に2行）
```

### 6-2. 設計上の抜け穴と塞ぎ方

| # | 抜け穴 | 起きること | 塞ぎ方 | 投稿での扱い |
|---|---|---|---|---|
| 1 | 記帳はプロンプト遵守（100%ではない） | 質問だけのセッションで記帳スキップ。中断セッションが `[ ]` のまま宙に浮く | trailerの保険で二段構え。確実性が欲しい人はHooksで強制（v0.2として） | 「100%」「必ず」を使わない |
| 2 | ID自己発番の衝突 | 並行セッションが同じ連番を振り得る | 人間発番を優先。自己発番は開始時刻入り（0804-1410）に | Q&A用意 |
| 3 | 台帳をコミットするとブランチごとに分裂 | 「1冊のノート」が嘘になる。エージェントが台帳を勝手にコミットへ混ぜて差分ノイズ・conflict | **.gitignoreに入れる**（使い方2に反映済み）。チーム共有したい場合は1タスク=1ファイル方式（`.ai/worklog/0804-1.md`）ならconflictゼロでマージ時ユニオンされる | 使い方2に反映済み + Q&A |
| 4 | worktree分離（ネタ4）と併用すると台帳がworktreeごとに分かれる | ネタ間の矛盾を突かれる | worktree併用時はtrailer+ブランチ名が主、台帳は補助と位置づける。共有台帳が要るなら1タスク=1ファイル方式をコミット運用 | ネタ4投稿時に一言添える |
| 5 | squashマージでtrailer消滅 | squash運用チームでは履歴側の保険が弱い | Task IDをPRタイトルに入れる（squash後のコミットタイトルに残りgrep可）。またはrebaseマージ | Q&A用意 |

### 6-3. 想定問答（リプ対応用）

- **Q. トークン消費増えない？** → 規約5行≒150トークン/セッション + 記帳数百トークン。コーディングセッションは数万〜数十万トークンなので誤差（0.1%前後）。台帳を数十行に保つことだけ注意。
- **Q. LLMが指示なんて守らない** → だからコミットtrailerと二段構え。100%が欲しければHooksで機械的に強制できるが、まず5行で回るかを試す設計（薄く出す方針）。
- **Q. AI_WORKLOG.mdがconflictするだろ** → 既定は.gitignore運用なのでconflictしない。チーム共有するなら1タスク=1ファイル方式。
- **Q. squashで消えるよ** → 消える（実測済み）。squash運用ならTask IDをPRタイトルへ。台帳側は影響なし。
- **Q. Claude CodeはAGENTS.md読まないぞ** → 読まない（2026-07時点・Issue #34235）。だからCLAUDE.mdに`@AGENTS.md`の1行を書く手順にしている。
- **Q. Geminiでも使える？** → Gemini CLIは settings.json の `contextFileName` を AGENTS.md にすれば同じ台帳に合流できる。ブラウザ版Geminiは対象外。
- **Q. どのセッションかまでは分からなくない？** → ツール名+ブランチ+一言までは1秒。resume一覧の絞り込みが「2ツール総当たり」から「1行」になるのが効能。セッションIDの自動記録はスキル化（v0.2）の課題。
- **Q. 貼ったのに効かない** → AGENTS.mdはセッション開始時に読まれる。開きっぱなしのセッションには効かないので、新しいセッションで試す。

### 6-4. 判定

**GO（修正3点の反映後）。**

1. 日報コマンドに `separator=` を追加（反映済み。旧版は表が崩れる実バグ）
2. 使い方に「.gitignoreに入れる」を追加（反映済み。台帳分裂・差分ノイズの予防）
3. 「全部のAIが読む」「必ず」「100%」系の言い切りをしない（ドラフトは元から回避済み）

技術クレームは実測と一次情報で裏取り済み。残る不確実性は「記帳遵守率」だが、
trailerの二段構え設計と誠実な言い回し（Q&A準備込み）でカバーする。

## 7. 投稿パッケージ（本文140字 + リプ構成）

導入は「導入プロンプト1本を、CodexかClaude Codeのどちらか片方に1回渡すだけ」で完結する。
仕組みの実体はリポジトリ内のファイル4つ（AGENTS.md / CLAUDE.md / .gitignore / AI_WORKLOG.md）で、
誰が作っても同じ。Claude Codeは次セッション開始時に CLAUDE.md → `@AGENTS.md` を自動で読み、
CodexはAGENTS.mdを直接読むため、作った本人かどうかは無関係。ツール別プロンプトの2本立ては不要。

### 本文（約110字）

```text
CodexとClaude Code併用勢の「この修正どっちに頼んだっけ」。原因は記憶力じゃなく、記録が各ツールの中に閉じてること。リポジトリに台帳を1枚置き、AI自身に記帳させるルールを仕込むと消えます。導入はどっちか片方のAIに1回頼むだけ。プロンプトはリプに🧵
```

### リプ1: 導入プロンプト（どちらか片方に1回貼る）

```text
このリポジトリに「AI作業台帳」を導入して。既存ファイルは上書きせず追記で。やることは4つ:

1. AGENTS.md（無ければ作成）に次のセクションを追記

## エージェント共通規約（全AIツール共通）
- 作業開始時: リポジトリ直下の AI_WORKLOG.md の先頭に1行追記（無ければ作成）
  形式: - [ ] ID | ツール名 | ブランチ | 依頼の一言 | 開始 MM/DD HH:MM
  例:   - [ ] 0804-1 | codex | fix/login | ログイン修正 | 開始 08/04 14:10
- 作業終了時: 自分の行を更新（済は [x]+結果を一言、未完は「次の一手」を書く）
- コミットメッセージ末尾に Task: <ID> と Agent: <ツール名> の2行を付ける
- IDは指示に無ければ「日付-開始時刻」（例: 0804-1410）で自分で振り、最初の返答で宣言する

2. CLAUDE.md（無ければ作成）に @AGENTS.md の1行を追記（既にあれば何もしない）
3. .gitignore に AI_WORKLOG.md を追加
4. 空の AI_WORKLOG.md を作成

終わったら変更ファイルの一覧を報告して。
```

長さは約450字。X無料枠（全角約140字/ポスト）には収まらないため、
Premiumの長文ポスト / 「1」と「2〜4」で2リプに分割 / リポジトリのファイルへのリンク、のいずれかで出す
（コピペで完結が配布方針なので画像化はしない）。

### リプ2: なぜ片方に1回でいいのか

```text
「Codex側とClaude側、両方に設定が要るのでは？」→ 要らない。仕組みの実体は"リポジトリに置くファイル"だけで、誰が作っても同じ。Claude Codeは次のセッション開始時にCLAUDE.md→@AGENTS.mdを自動で読むし、CodexはAGENTS.mdを直接読む。作った本人かどうかは関係ない。※効くのは「新しいセッション」から。開きっぱなしの画面には効かない
```

### リプ3: 導入後の使い方

```text
使い方は普段どおり頼むだけ。
・こだわるなら「0804-1として〜」とID付きで依頼
・「どっちに頼んだっけ」→ AI_WORKLOG.md を開く（1秒で決着）
・台帳は数十行に保つ（週1で済み行を消す）
```

### リプ4: 合同日報コマンド + 保険の説明

```text
おまけ。週末にこれを打つと「今週どっちに何をやらせたか」の合同日報が出る。

git log --since='1 week ago' --date=short --format='%ad %h %(trailers:key=Agent,valueonly,separator=) %s'

記帳はAIがたまに忘れる（プロンプト指示なので100%ではない）。だからコミット側の Task: / Agent: が保険。台帳とgit logの二段構えです
```

### 補足（投稿には載せない設計メモ）

- 導入プロンプトの規約に「無ければ作成」を入れてあるのは、台帳が.gitignore対象で
  クローンに含まれないため（新しいマシンでも自己修復的に台帳が生えるようにする）
- 既存のCLAUDE.mdに中身がある場合、その中身はCodexからは見えないまま残る。
  完全一元化（中身をAGENTS.mdへ移す）はネタ2の領分なので、この投稿では触れない
- IDの既定を「日付-開始時刻」にしたのは並行セッションの連番衝突を避けるため（抜け穴#2の対応）。
  人間がID指定した場合はそちらが優先
