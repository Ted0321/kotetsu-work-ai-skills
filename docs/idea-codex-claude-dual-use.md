# Codex × Claude 二刀流の悩みマップとX投稿ネタ

CodexとClaude Codeを併用する人（二刀流）特有の悩みを分解し、解決の型・X投稿ネタ・スキル化候補に落とすための作業メモ。

## 結論（1行）

二刀流の悩みの根っこは1つ。**作業の記録とルールが、各ツールの中に閉じていること。**
だから解決の原則も1つ。**記録・ルール・タスクIDをツールの外（リポジトリ側・人間側）に出す。**

「どっちに何を頼んだか分からない」は記憶力の問題ではなく、置き場所の設計の問題。
セッション履歴はClaudeは `~/.claude/projects/`、Codexは `~/.codex/sessions/` と別々に積まれ、
さらにWeb版・IDE拡張で「面」が増える。ツール内の履歴を追いかける限り、この分断は解けない。

## 1. 悩みマップ（4層×12個）

### 層1: 記録・追跡 — 本丸

| # | 悩み | 具体 |
|---|---|---|
| 1-1 | タスク行方不明 | 「この修正どっちに頼んだっけ」。`claude --resume` と `codex resume` の一覧を両方開いて探す。Web版・IDE拡張も含めるとセッションの置き場が4面以上ある |
| 1-2 | 履歴の分断 | 「今週AIに何をやらせたか」が出せない。ログ形式が別、ブランチ接頭辞が別（`claude/` と `codex/`）、コミットの署名も別。バグの犯人捜し（どっちが入れた変更か）も難しい |
| 1-3 | 再開の摩擦 | 作業のつづきをやるには「どっちのツールの文脈にあるか」を先に思い出す必要がある。文脈はツール間で共有されないので、途中乗り換えは実質やり直し |

### 層2: 設定・資産の二重管理

| # | 悩み | 具体 |
|---|---|---|
| 2-1 | メモリのドリフト | CLAUDE.md と AGENTS.md を別々に育てると中身がズレて、同じリポジトリで2体が違うルールで動く |
| 2-2 | スキルの二重導入 | `.claude/skills/` と `.agents/skills/` に同じものを2回入れる。片方だけ更新して挙動が割れる |
| 2-3 | MCPの二重設定 | `.mcp.json` と `config.toml` に同じサーバーを2回書き、認証も2回。バージョンもズレる |

### 層3: 運用中の事故・干渉

| # | 悩み | 具体 |
|---|---|---|
| 3-1 | 同一作業ツリー衝突 | 2体を同じチェックアウトに入れて同時編集・lockファイル・devサーバーのポートが衝突 |
| 3-2 | モード誤認 | plan mode / read-only、承認モードの意味がツールで違う。Claudeのつもりでスラッシュコマンドを空振りし、Codexのつもりで全権を渡す |
| 3-3 | コードの方言 | コミット文体・コメント量・命名の癖が2流派になり、レビュー観点（各モデルの死角）も2セット必要になる |

### 層4: 判断・頭の使い方

| # | 悩み | 具体 |
|---|---|---|
| 4-1 | ルーティング迷い | 毎回「これどっちに投げるか」を考える。切り替えの意思決定コストが積もる |
| 4-2 | クォータやりくり | 5時間枠・週次上限が2系統。枠の都合で途中乗り換えが起き、それが層1を悪化させる |
| 4-3 | 評価が印象論 | 「Codexの方が○○に強い気がする」が検証できない。記録が無いから使い分けが上達しない |

### 因果ループ（層1を最初に解くべき理由）

```text
クォータ切れ(4-2) → 途中乗り換え → 記録の分断(1-1, 1-2) → 使い分けの根拠が残らない(4-3)
→ 毎回迷う(4-1) → また場当たりで乗り換える → …
```

分断の起点は層1。ここに台帳を置くと、4-1と4-3も自動的に解け始める。

## 2. 解決の型（今日できる順）

| # | 型 | 内容 | 解く悩み |
|---|---|---|---|
| A | 作業台帳 | リポジトリ直下に `AI_WORKLOG.md`。開始時に1行追記・終了時に更新を両エージェントに義務付け | 1-1, 1-2 |
| B | ID発番は人間 | タスクIDを人間が振る（日付+連番で十分）。ブランチ・台帳・コミットに同じIDを通す | 1-1, 1-2 |
| C | コミットtrailer | `Agent: codex` / `Agent: claude` と `Task: 0803-1` を必ず付けさせる。git logがそのまま合同日報になる | 1-2, 4-3 |
| D | 引き継ぎ書 | 乗り換え時は今のエージェントに `HANDOFF.md`（目的/済/未/ハマり/次の一手/確認方法）を書かせてから移る | 1-3, 4-2 |
| E | メモリ一元化 | AGENTS.md を正とし、CLAUDE.md は `@AGENTS.md` の1行だけにする。共通規約はAGENTS.mdの「エージェント共通規約」節に書く（1か所に書けば2体に効く） | 2-1, 2-2 |
| F | worktree分離 | 1エージェント=1worktree。devサーバーのポートも固定割当 | 3-1 |
| G | ルーティング3行 | 自分の決め打ち表を作って迷いを消す。台帳の結果で月1回見直す | 4-1, 4-3 |
| H | 週次AI日報 | 2ツールのセッションログ+git logを束ねて「今週AIにやらせたこと」を自動生成（将来のスキル化候補） | 1-2, 4-3 |

### A+B+C: 共通規約コピペ（フラッグシップ）

AGENTS.md（とCLAUDE.mdの `@AGENTS.md` 経由）に貼る5行。これだけで「どっちに頼んだっけ」が消える。

```markdown
## エージェント共通規約（Codex / Claude 共通）
- 作業開始時: リポジトリ直下の AI_WORKLOG.md の先頭に1行追記する
  形式: `- [ ] 0803-1 | codex | ブランチ名 | 依頼の一言 | 開始 08/03 14:00`
- 作業終了時: 自分の行を更新する（済なら [x] と結果を一言。未完なら「次の一手」を書く）
- コミットには trailer `Task: 0803-1` `Agent: codex` を付ける
- タスクIDは人間の指示に無ければ「日付+連番」で自分で振り、最初の返答で宣言する
```

合同日報の出し方（例）:

```bash
git log --since='1 week ago' --date=short \
  --format='%ad %h %(trailers:key=Agent,valueonly) %s'
```

### D: 引き継ぎ書テンプレ（乗り換え5分ルール）

クォータ切れ・得意分野での乗り換え時に、離脱側へ最後に1回だけ依頼する。

```text
HANDOFF.md を書いて。項目は6つ:
1. 目的（このタスクは何ができたら終わりか）
2. 完了したこと（ファイル名つき）
3. 未完のこと（残作業を箇条書き）
4. ハマりどころ（試して駄目だった案と理由）
5. 次の一手（最初にやるべき1つ）
6. 確認方法（何を実行すれば動作確認できるか）
```

受け側の最初の指示は「HANDOFF.md を読んでから始めて」の1行。

### E: メモリ一元化の注意（Windows）

シンボリックリンクは管理者権限や開発者モードが要るので、CLAUDE.md に
`@AGENTS.md` と書くインポート方式が安全。リンクより壊れにくい。

### G: ルーティング3行（例。正解ではなく、台帳で自分の実測に更新していく）

```text
- 設計相談・仕様の壁打ち・長丁場のリファクタ → Claude
- 単発の修正・テスト生成・書き捨てスクリプト → Codex
- 失敗したくない重要変更 → 両方に同じIDで投げて突き合わせ（台帳に2行）
```

## 3. スキル化候補（このリポジトリ向け）

| ID案 | 一言 | 中身 | 出し方 |
|---|---|---|---|
| dual-agent-worklog | どっちに頼んだかを、探さない | 型A+B+C（共通規約+台帳フォーマット+日報コマンド） | v0.1はコピペ型（規約5行）→反応を見てエージェント型（台帳の自動追記・整形） |
| agent-handoff | 乗り換えても、文脈を捨てない | 型D（HANDOFF.md テンプレと受け渡し手順） | コピペ型。薄配布向き |
| ai-weekly-report | 今週AIに何をやらせたかが1枚で出る | 型H（2ツールのログ+git log集計） | エージェント型。実測スクショがX映えするので後発で |

いずれも「Claude CodeとCodexの両方で確認してから動作確認済みと表記」のROADMAP方針に乗せやすい
（そもそも両方で動くことが価値の中心のスキル群）。

## 4. X投稿ネタ案（優先順）

| # | フック（仮） | 配る物 | 形式 |
|---|---|---|---|
| 1 | 「この修正、CodexとClaudeどっちに頼んだっけ」を今日も探してませんか | 共通規約5行（型A+B+C） | 薄配布→スキル導線 |
| 2 | CLAUDE.mdとAGENTS.mdの二重管理、今日でやめられます | `@AGENTS.md` 1行の一元化手順 | 薄配布 |
| 3 | レートリミットで乗り換える前に、AIに書かせるもの1つ | HANDOFF.md テンプレ（型D） | 薄配布 |
| 4 | CodexとClaudeを同じフォルダに入れてはいけない | worktree分離の掟+ポート割当（型F） | 薄配布 |
| 5 | git logが「AIとの合同日報」になる設定 | trailer運用+日報コマンド（型C） | 薄配布 |
| 6 | 「どっちに投げるか」で毎回止まる人へ | ルーティング3行（型G） | 薄配布 |
| 7 | 今週AIにやらせた仕事、全部出してみた | 週次日報の実測スクショ（型H） | 実測系→スキル導線 |
| 8 | 二刀流の悩み、全部「記録がツールの中にある」せいだった | 悩みマップ4層の図解 | スレッド→リポジトリ導線 |

- 1が本丸（共感最大・即効・配布物が5行で薄い）。8をスレッドの親にして1〜7をぶら下げる構成も可
- 7は「Codexで頼んだ修正をClaudeに催促してた」系のあるある1行をフックに足すと引用されやすい

### ドラフト1: ネタ1（共通規約5行）

```text
CodexとClaude、両方使ってる人。
「この修正どっちに頼んだっけ」って今日も探してませんか。

原因は記憶力じゃなくて、記録が各ツールの中に閉じてること。
AGENTS.mdに5行貼るだけで、台帳が1つになります。

コピペ用：
・開始時に AI_WORKLOG.md へ1行追記
　`- [ ] 0803-1 | codex | ブランチ | 依頼の一言`
・終了時に自分の行を更新（済/未完+次の一手）
・コミットに Task: と Agent: を付ける
・IDが無ければ日付+連番で自分で振って宣言

使い方
1. 上をAGENTS.mdに貼る（CLAUDE.mdは @AGENTS.md の1行に）
2. 明日から「どっちに頼んだか」は台帳を見る
3. 週末に git log で合同日報を出す

保存して、次にセッションを見失う前に。
```

### ドラフト2: ネタ3（引き継ぎ書）

Claudeのレートリミットが来た瞬間、Codexに乗り換えて
ゼロから説明し直してる人、損してます。

乗り換える前に、AIに1つだけ書かせてください。

コピペ用：「HANDOFF.md を書いて。項目は6つ」
1. 目的（何ができたら終わりか）
2. 完了したこと（ファイル名つき）
3. 未完のこと
4. ハマりどころ（試して駄目だった案）

1. 枠が切れそうになったら上を貼る
2. 乗り換え先の最初の指示は「HANDOFF.mdを読んで」の1行
